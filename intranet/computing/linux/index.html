Computing Resources Centre

Linux and SSH: enough to get started

A short working introduction for people whose research is about to need a machine they cannot walk up to. Not a course — the twenty-odd commands that account for most of a first week, in the order you meet them.

How to read this page

The commands here are real; the addresses in them are not

Everything on this page works on any Linux or macOS machine, including the one in front of you, and it is worth trying there first. Where a command needs a host or an account, that part is a placeholder in capitals inside angle brackets and the block is marked as a sample — because this university has no host to name yet.

Nothing here is specific to MIT-WPU, and that is deliberate: what you learn on your own laptop is what you will type on somebody else's supercomputer.

The shell, and where you are

A shell is a program that waits for you to type the name of another program. That is all it is. The prompt tells you which machine you are on and which directory you are in, and the single most common cause of a confusing afternoon is being wrong about one of those two.

Six commands account for most of what anyone does. Learn these and the rest can be looked up.

Where am I, and what is here 

# Print working directory: the folder you are in, as a full path.pwd# List what is in it. -l for one per line with detail, -a to include the hidden dot-files.ls -la# Change directory. A bare cd goes home; cd .. goes up one.cd <DIRECTORY>

Making, copying, moving, removing 

mkdir results# Copy. -r to copy a whole directory.cp -r results results-backup# Move — which is also how you rename.mv results-backup old-results# Remove. There is no undo and there is no wastebasket.rm old-results/notes.txt

rm -rf is the command that ends careers. It deletes a directory and everything under it without asking, and a stray space in the wrong place makes the argument something much larger than you meant. Read the line before pressing return, every time.

When you do not know what a command does 

# The manual is on the machine and does not need a network.man ls# Most modern commands answer this too.ssh --help

Press q to leave the manual. Not knowing that is the reason most people leave it by closing the window.

Files, and who may do what to them

Every file carries three permissions — read, write, execute — for three audiences: you, your group, everybody else. `ls -l` shows them as nine characters. This is worth ten minutes now, because SSH refuses to use a private key whose permissions are wrong and the error message does not say so plainly.

The numbers are the same three permissions written as bits: 4 read, 2 write, 1 execute, added together per audience. So 600 is "I may read and write it, nobody else may do anything", and 755 is "I may do anything, everybody else may read and run it".

600
Yours alone, read and write. What a private key must be.
644
Yours to edit, everyone else's to read. The default for an ordinary file.
700
Yours alone, including entering it. What ~/.ssh must be.
755
Yours to change, everyone else's to enter or run. The default for a directory or a script.

Read the permissions, then set them 

# The first ten characters of each line are the type and the nine permissions.ls -l ~/.ssh# The two that SSH insists on.chmod 700 ~/.sshchmod 600 ~/.ssh/id_ed25519# A script you want to be able to run by name.chmod 755 <YOUR-SCRIPT>.sh

"Permissions 0644 for 'id_ed25519' are too open" is SSH refusing to use a key anybody on the machine could read. chmod 600 is the whole fix.

SSH keys: what they are and how to make one

A key pair is two files. The public half is not a secret and is what you hand out; the private half is the secret and never leaves the machine it was made on. A remote system that has your public half can check that you hold the private half without ever seeing it, which is why this is better than a password and why no shared facility issues passwords for it.

One key per person, not one per machine you connect to. If you work from a laptop and a desktop, that is two keys, and both public halves get registered.

Make a key pair

Two minutes, once, on each machine you will connect from.

Applies to macOS and Linux, and Windows 10 or later in PowerShell or WSL.

  1. Check whether you already have one

    List the keys on this machine 

    ls -l ~/.ssh/id_*.pub

    A file ending in .pub means you have a key. Use it. Making a second one does not add security and does add a thing to keep track of.

  2. Generate the pair

    Generate an ed25519 key pair 

    # ed25519 rather than RSA: shorter, faster, and the current default everywhere.ssh-keygen -t ed25519 -C "<YOUR-NAME>-<MACHINE>"

    What you should see

    Enter file in which to save the key (~/.ssh/id_ed25519):Enter passphrase (empty for no passphrase):

    Accept the default file name by pressing return. The comment after -C is only a label to help you tell keys apart later.

    Give it a passphrase. It is asked for once per session rather than once per connection, and it is the only thing standing between a stolen laptop and everywhere that laptop could reach.

  3. Add it to the agent so the passphrase is asked once

    Hold the unlocked key for this session 

    ssh-add ~/.ssh/id_ed25519# What the agent currently holds.ssh-add -l

  4. Send the public half — and only the public half

    Print the public half, to paste into a form or a message 

    cat ~/.ssh/id_ed25519.pub

    What you should see

    ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI<...>  <YOUR-NAME>-<MACHINE>

    One line, beginning ssh-ed25519. If what you are looking at is many lines beginning with five dashes and the word BEGIN, you have opened the private half. Close it and do not send it.

You have a key when cat prints one line beginning ssh-ed25519, and ssh-add -l lists it.

Connecting, and the fingerprint nobody checks

The first connection to any machine asks you to confirm its fingerprint. That prompt is the only moment at which you can tell the machine you meant from something standing in front of it, and it is the moment everyone clicks through. Compare it with what the service published, once, and the machine is remembered afterwards.

Open a session Sample. Everything in <ANGLE BRACKETS> is a placeholder for you to replace, and the values here are not this service's real ones. 

# SAMPLE — placeholder values, not this service's real ones.ssh <YOUR-USERNAME>@<HOST-YOU-WERE-GIVEN>

What you should see

The authenticity of host '<HOST-YOU-WERE-GIVEN>' can't be established.ED25519 key fingerprint is SHA256:<FINGERPRINT-THE-HOST-OFFERS>.Are you sure you want to continue connecting (yes/no/[fingerprint])?

Type exit, or press Ctrl-D, to come back.

When it will not connect, ask it why Sample. Everything in <ANGLE BRACKETS> is a placeholder for you to replace, and the values here are not this service's real ones. 

# SAMPLE — placeholder values, not this service's real ones.# -v once for a little, -vvv for more than you want.ssh -v <YOUR-USERNAME>@<HOST-YOU-WERE-GIVEN>

The useful lines are the ones naming which key was offered and what the server said about it. "Permission denied (publickey)" almost always means the public half was never registered, or the private half is not the one being offered.

Making it one word

`~/.ssh/config` on your own machine turns an address you would otherwise retype into a short name. It is read by ssh, scp and rsync alike, so setting it up once fixes all three, and it is the single highest-value ten minutes on this page.

A host entry in ~/.ssh/config Sample. Everything in <ANGLE BRACKETS> is a placeholder for you to replace, and the values here are not this service's real ones. 

# SAMPLE — placeholder values, not this service's real ones.# Indentation is conventional rather than required; keep it anyway.Host <SHORT-NAME-YOU-CHOOSE>    HostName <FULL-ADDRESS-YOU-WERE-GIVEN>    User <YOUR-USERNAME>    IdentityFile ~/.ssh/id_ed25519# Keeps a session from being dropped while you think.    ServerAliveInterval 60

And then, from anywhere Sample. Everything in <ANGLE BRACKETS> is a placeholder for you to replace, and the values here are not this service's real ones. 

# SAMPLE — placeholder values, not this service's real ones.ssh <SHORT-NAME-YOU-CHOOSE>scp <FILE> <SHORT-NAME-YOU-CHOOSE>:

The config file itself should be readable only by you: chmod 600 ~/.ssh/config.

Moving files between machines

`scp` for one file, `rsync` for everything else. rsync copies only what differs, resumes an interrupted transfer and can be run again safely — which is what you want the moment the thing being copied is larger than a coffee break.

One file, up and then back Sample. Everything in <ANGLE BRACKETS> is a placeholder for you to replace, and the values here are not this service's real ones. 

# SAMPLE — placeholder values, not this service's real ones.scp <LOCAL-FILE> <SHORT-NAME-YOU-CHOOSE>:<REMOTE-PATH>scp <SHORT-NAME-YOU-CHOOSE>:<REMOTE-FILE> .

The lone dot means "into the directory I am in now".

A directory, resumably Sample. Everything in <ANGLE BRACKETS> is a placeholder for you to replace, and the values here are not this service's real ones. 

# SAMPLE — placeholder values, not this service's real ones.# -a preserves permissions and times, -v narrates, --partial keeps what arrived before a drop.rsync -av --partial <LOCAL-DIRECTORY>/ <SHORT-NAME-YOU-CHOOSE>:<REMOTE-DIRECTORY>/# Show what WOULD be copied and copy nothing. Worth doing first, every time.rsync -avn --partial <LOCAL-DIRECTORY>/ <SHORT-NAME-YOU-CHOOSE>:<REMOTE-DIRECTORY>/

The trailing slash on the source is not decoration. With it, the contents are copied; without it, the directory itself is copied inside the target, which is how people end up with results/results/results.

Keeping work alive when your connection drops

Close a terminal and everything running in it dies with it, which on a train is a two-hour job lost at ninety minutes. `tmux` puts the session on the far end of the connection rather than in your terminal, so it survives the connection going away and is still there when you come back.

Three commands is the whole of what most people need.

Start, leave, and come back 

# Start a named session. Name it after the work, not after the day.tmux new -s analysis# Detach: press Ctrl-b, let go, then press d. The session keeps running.# Ctrl-b  then  d# What is still running.tmux ls# Reattach, from the same machine or a different one.tmux attach -t analysis

Ctrl-b is tmux's attention key: every tmux command is Ctrl-b followed by something. Ctrl-b then c makes a new window inside the session, Ctrl-b then n moves to the next one.

Why you do not run your work on the machine you logged in to

On a shared research system the machine you land on is a doorway, not a workshop. It is shared with everyone else currently connected, and a calculation started there slows all of them down; most facilities kill such processes automatically, and some suspend the account.

Instead you describe the work in a small script and hand it to a scheduler, which runs it unattended on machines you never log in to. There are several schedulers and their commands differ, but all of them ask the same four questions, and having the answers is what makes the difference between a first day that works and one that does not.

How many processors?
More than your program can actually use makes the wait longer and the bill bigger, not the run faster.
For how long?
Your honest estimate plus a margin. Under-ask and it is killed part-way; over-ask and it queues behind everything else.
How much memory?
The commonest reason a long job dies overnight leaving nothing useful behind.
Charged to what?
Time is granted to a project rather than to a person, so a submission normally names one.

What this page deliberately does not cover

It is a first week, not a course. Shell scripting beyond a straight run of commands, package and environment management, version control, containers, parallel programming and performance measurement are each larger than everything above put together, and a page that gestured at them would teach nobody anything.

The university publishes no training in any of it, and no reading list. That is on the work list below rather than filled in here with somebody's favourite links: a recommendation is an institutional statement, and this page does not make those on the university's behalf.

What this page cannot yet tell you

This page is the most nearly complete of the five, because almost none of it depends on a decision this university has yet to take. What is missing is the part only an institution can supply: whether anybody teaches this, to whom, and who answers a question about it.
